# WorldCupScan — 数据分类总谱

> **制表日期**：2026-06-23 | **最新更新**：2026-06-29 v5（淘汰赛修正）
> **核心原则**：
> 1. **最高等级确保数据真实性和实时性** → 必须调 API 的数据绝不读本地
> 2. **基础稳定数据** → 可用本地，但必须确保内容正确
> 3. **API 失败静默降级** → 降级到本地时不让用户感知，不弹错误提示
> 4. **淘汰赛对阵不能靠本地** → 对手根据前一场结果实时决定，打包时无法预知

---

## 一、一句话总结

```
比分、积分、榜单、事件、阵容、统计、MVP、射门图、淘汰赛对阵 → 🔴 必须调 API
球员名字、球队分组、场馆、FAQ                              → 🟢 读本地就行
球员照片、队徽、荣誉、预测、BDL高级数据                     → 🟡 有条件调 API
```

## 二、🔴 必须调 API 的数据（共 20+ 端点）

> 不调 API 就没有实时数据，显示的是 0-0 或 null。

### 2.1 football-data.org（免费，10次/分钟）

| 数据 | 大白话解释 | 用在哪儿 |
|:-----|:----------|:---------|
| **全部比赛比分+状态** | 每一场谁对谁、几比几、踢没踢完。本地 `matches.json` 存的是 0-0，不调 API 就是错的。 | Tab C 赛程列表、比赛详情比分板 |
| **实时比分** | 正在直播的比赛，30 秒轮询一次，比分变了立刻更新。 | Tab A 实时赛况 |
| **小组积分榜** | 12 个小组的排名，赢 3 分平 1 分输 0 分，每场赛后都变。 | Tab D 积分榜子 Tab |
| **射手榜** | 谁进球最多、排第几。 | Tab D 球员榜子 Tab |
| **球员世界杯累计** | 某球员本届世界杯总共进了几球、出场几次、踢了多少分钟。 | PlayerDetailActivity 的 12 项累计统计 |
| **球队信息（含队徽 URL）** | 48 队的基本信息 + 队徽图标链接。队徽不变，所以一次拉取永久缓存。 | TeamDetailActivity 的 crest |
| **淘汰赛对阵** | 16 强谁打谁、8 强谁打谁。**淘汰赛对手根据前一场结果实时决定，不能用本地。** | Tab D 淘汰赛对阵图 + 比赛详情 |

### 2.2 api-sports.io（Pro $19/月，7500次/天）

| 数据 | 大白话解释 | 用在哪儿 |
|:-----|:----------|:---------|
| **比赛事件** | 谁进了球、谁吃了牌、谁被换下，含 VAR 判定。赛中就能看到。 | 比赛详情 » 赛况 Tab |

| **球员单场 18 项统计** | 某球员某一场的评分、射门、传球、抢断等详细数据。 | 比赛详情球员弹窗 |
| **球员赛季累计 18 项** | 某球员本届世界杯的射门总数、传球总数、评分均值等。 | PlayerDetailActivity 的赛季统计区 |
| **球队阵容（含号码+照片）** | 每支球队 26 人的名单、球衣号码、照片链接。 | 球队卡、照片加载 |
| **历史交锋 H2H** | 两队历史上碰过几次、谁赢得多。 | **已删除，不再使用** |

## 三、🟡 有条件调 API 的数据（共 5 类）

> 调也行，不调也能用本地，数据变化频率低。

| 数据 | 大白话解释 | 为什么可以本地 | 用在哪儿 |
|:-----|:----------|:-------------|:---------|
| **球员照片** | 球员头像，用 Coil 加载圆形裁剪。 | URL 存在本地 JSON 里，路径固定，只是加载走网络。 | 所有页面的球员头像 |
| **队徽 crest** | 球队的官方队徽图标。 | 队徽不会变，调一次 football-data 就能永久缓存。 | TeamDetailActivity 头部 |
| **球员生涯荣誉** | 梅西拿过几个欧冠、几个金球奖。 | 奖杯列表赛季才变一次，本地已有 780+ 人的 `trophies_cache.json`。 | PlayerDetailActivity 荣誉墙 |
| **比赛预测** | AI 算的胜平负概率。 | MC 模型赛前算好的，赛中不会变。 | 比赛详情预测卡片 |
| **BDL 高级数据（xG/xA/传中/头球）** | 预期进球、预期助攻、传中次数等。 | 赛后才有值，赛中调了也白调。 | PlayerDetailActivity 高级统计区 |

## 七、淘汰赛特殊说明

### 7.1 核心原则：知道赛果 = 知道赛程

```
小组赛完全结束
   ↓ 手动填入（仅一次）
1/16决赛对阵确定 ✅（已完成手动填入）
   ↓ 每场比赛结束后自动推演
1/8决赛 → 1/4决赛 → 半决赛 → 决赛（自动更新）
```

**淘汰赛的本质**：对阵路线图是固定的——1/16决赛的第N场的胜者一定去1/8决赛的第M场。所以：

```
1/16决赛 巴西 vs 日本 → 巴西 2-0 日本
   ↓ 自动推演
1/8决赛 slot#3 = "巴西 vs 某队"
   ↓ 推演逻辑：读比赛结果 → 判断胜者 → 查晋级路线图 → 写入下一轮slot
```

**不需要手动更新赛程**。只需要写一个脚本，每场比赛结束后自动执行：
1. 调 API 或读 matches.json 获取比分
2. 判断胜者
3. 按对阵图规则（A组出线打B组出线等）填入1/8决赛对应slot
4. 递归，直到所有淘汰赛确定

### 7.2 1/16决赛对阵（手动填入，已完成 ✅）

小组赛结束后，32支晋级球队确定，1/16决赛的16场对阵已手动填入 `matches.json`：

```json
// 实际格式
"homeTeam": "Brazil", "awayTeam": "Japan",    // ✅ 直接写球队名
"round": "1/16决赛", "type": "knockout"
```

### 7.3 1/8决赛及以后（自动推演）

自动脚本《淘汰赛自动推演引擎》的工作流程：

```
Input: 已完赛的淘汰赛比分（从API或本地）
             ↓
      读取对阵图规则（bracket.json / 硬编码路线表）
             ↓
      判断胜者 → 填入下一轮slot
             ↓
      更新 matches.json → 重新生成 predictions.json
             ↓
Output: 更新后的淘汰赛对阵
```

脚本位置：`outputs/auto_update_bracket.py`

### 7.4 fixture ID 说明

淘汰赛的 api-sports fixture ID 可以在比赛确定后通过按日期查询获得：

```python
GET /fixtures?date=2026-07-05  # 查某天的比赛
→ 拿到该日所有世界杯淘汰赛的 fixture ID
→ 写入 fixture_id_map.json
```

目前16场1/16决赛的 fixture ID 已全部获取并存储在 `fixture_id_map.json`（格式为 `{"api_sports_fixture_id": 1562344}`）。
