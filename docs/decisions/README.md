# 📝 工程决策记录

这 5 篇文档记录了世界杯项目从构思到交付的**完整心路历程**。它们不是普通的开发笔记——每一篇都对应着一个真实的工程决策和成长。

## 推荐阅读顺序

| 顺序 | 文件 | 读什么 |
|:---:|:-----|:-------|
| ① | `architecture_evolution.md` | 架构从 v2.1→v2.5 的三次演进，从"以比赛为中心"到"以球员-球队为中心" |
| ② | `requirement_journey.md` | 需求清单 10 个版本的迭代史——从乐观清单到数据事故、从假数据到真实 API |
| ③ | `fake_data_cleanup.md` | **我主动审计并洗掉了所有假数据的故事**——这是我最自豪的一次提交 |
| ④ | `data_classification.md` | 20+ API 端点的三级分类战略（🔴必须/🟡条件/🟢基础本地） |
| ⑤ | `data_reliability.md` | 数据管线逐层可靠性审计——覆盖率、风险点、修复记录 |

## 为什么放这些？

面试官看完会说："这人不仅会写代码，还知道怎么思考。"

- **架构设计能力** → 从失败的 AR 方案及时止损，主动重构架构
- **工程诚信** → 敢承认"这份文档第一次说真话"，敢公开审计假数据
- **战略思维** → API 三级分类、优雅降级、跨 Tab 数据共享
- **数据质量意识** → 逐层管线审计，有覆盖率、有修复记录
